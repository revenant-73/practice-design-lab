# The Practice Design Lab Course Design Rules

## Purpose

These rules define the form and function of courses within **The Practice Design Lab**.

They are meant to create continuity, consistency, and a highly engaging modern learning experience that is visually impressive while still helping coaches learn and apply the course topic.

These are the constraints the course itself must follow.

---

# 1. Core Function Rule

Every course must help the coach **do something usable in practice**, not just understand an idea.

For **Constraints: Upgrade Any Activity**, the learner must finish with:

- An activity they already use
- A clearer problem
- An attention target
- One meaningful constraint
- A coaching question
- An adjustment plan

If a module does not help build that final outcome, cut it.

---

# 2. One Screen, One Job

Each screen should teach, ask, test, or apply **one clear thing**.

Avoid screens that try to:

- Define a concept
- Give three examples
- Ask a reflection question
- Introduce a new framework
- Quiz the learner

Pick one main function per screen.

Good screen types:

- Teaching screen
- Illustration screen
- Reflection screen
- Scenario screen
- Quiz screen
- Builder screen
- Summary screen

---

# 3. The Course Must Feel Interactive Early

Do not make the learner read for five screens before doing anything.

By **Screen 1 or 2**, they should already be asked to think, choose, type, sort, or apply.

The course should feel like:

> “I am building something as I go.”

Not:

> “I am reading a long article broken into slides.”

---

# 4. Every Module Must Produce One Piece of the Final Build

Each module should add one part to the final activity upgrade.

Example structure:

- **Module 1:** Choose an activity
- **Module 2:** Identify the real problem
- **Module 3:** Decide what players need to notice
- **Module 4:** Choose one constraint lever
- **Module 5:** Build the upgraded activity
- **Module 6:** Create the adjustment plan

This creates momentum and makes completion feel meaningful.

---

# 5. Keep the Activity Recognizable

The course should constantly reinforce:

**Do not make practice weird. Make the problem clearer.**

That means examples should show small, meaningful changes:

- Change the scoring
- Change the space
- Change the number of players
- Change the starting situation
- Change the role
- Change the pressure

Avoid examples that feel like a completely different game unless that is the point of the lesson.

---

# 6. Use Plain Coaching Language

Avoid academic overload.

Use:

- Problem
- Activity
- Player attention
- Decision
- Space
- Pressure
- Teammate
- Opponent
- Timing
- Better solution

Use ecological language only when it helps.

Do not lead with:

- Affordances
- Perception-action coupling
- Self-organization
- Representative learning design
- Constraints-led approach theory

Those ideas can shape the course, but they should not burden the learner.

---

# 7. Multi-Sport First, Sport-Specific Second

The course should speak to **team sport coaches broadly**.

Primary language should use:

- Players
- Teammates
- Opponents
- Space
- Pressure
- Scoring
- Support
- Communication
- Decision-making
- Game problem

Sport-specific examples can appear, but rotate them:

- Volleyball
- Basketball
- Soccer
- Lacrosse
- Hockey
- Rugby
- Flag football

The main framework should not feel volleyball-only.

---

# 8. Use Examples in a Repeating Pattern

Every worked example should follow the same structure:

## Original Activity

What the coach already uses.

## Problem

What is breaking down.

## What Players Need to Notice

The attention target.

## Constraint

The one meaningful change.

## Why It Works

How the change shapes the problem.

## Coaching Question

One question the coach can ask.

This repetition builds confidence.

---

# 9. Every Quiz Must Teach

Quizzes should not just check memory.

They should sharpen judgment.

Use quiz types like:

- Best answer
- Choose the better constraint
- Spot the vague problem
- Match problem to constraint
- Too easy / too hard / too weird
- Telling vs designing
- Useful vs noisy communication

Every answer should include feedback.

## Correct Feedback Example

> Yes. This constraint matches the problem and rewards the behavior we want players to notice.

## Incorrect Feedback Example

> Not quite. This adds difficulty, but it does not address the real problem.

No shame. Just useful correction.

---

# 10. Open-Ended Questions Must Build Toward Action

Do not ask reflection questions just to sound interactive.

Every open-ended question should help the coach build their own practice upgrade.

## Weak Prompt

> What did you think of this idea?

## Better Prompt

> What is one activity you already use where players are busy, but the learning problem is unclear?

## Best Prompt

> Write one activity you already use. Then name one behavior you keep correcting during that activity.

---

# 11. Visuals Must Teach, Not Decorate

Every illustration should help explain the concept.

Use visuals like:

- Before / after activity comparison
- Problem → constraint → player noticing map
- Constraint lever wheel
- Decision flowchart
- Too easy / too hard / too weird adjustment tree
- Small-sided activity diagrams
- Coach observation notes
- Player attention spotlight

Avoid:

- Generic athlete hype images
- Motivational stock imagery
- Random sports equipment
- Diagrams that look impressive but teach nothing

---

# 12. Visual Style Rules

The visual style should feel:

- Modern
- Human
- Clean
- Coach-facing
- Slightly field-guide inspired
- Visually warm, not corporate

Suggested style:

- Warm cream background
- Black ink-style linework
- Teal for structure, arrows, and highlights
- Coral for small emphasis marks
- Subtle paper texture
- Clean sans-serif headings
- Simple hand-drawn accents

Avoid:

- Glossy corporate training graphics
- Cluttered whiteboard chaos
- Cartoonish kid imagery
- Overly technical diagrams
- Motivational poster energy

---

# 13. Screen Layout Rules

Each screen should be easy to scan.

Recommended layout:

- Clear title
- Short teaching block
- One visual or interaction
- One takeaway or action

Text limits:

- **Teaching screen:** 80–140 words
- **Reflection screen:** 30–70 words
- **Quiz screen:** short scenario + answer choices
- **Summary screen:** 3–5 bullets max

If a screen feels dense, split it.

---

# 14. Engagement Rhythm

Each module should rotate through this rhythm:

1. Hook
2. Short teaching
3. Visual explanation
4. Quick check
5. Scenario
6. Open response
7. Application
8. Summary

Do not stack too many teaching screens in a row.

After two teaching screens, the learner should do something.

---

# 15. The Learner Should Feel Smart, Not Tested

The tone of the course should be:

- Practical
- Direct
- Encouraging
- Curious
- Low-jargon
- Lightly challenging

Avoid sounding like:

- A professor
- A certification exam
- A coaching guru
- A motivational speaker
- A theory lecture

The learner should feel like:

> “This makes sense. I can try this.”

---

# 16. Built-In Troubleshooting Rule

Every course must include troubleshooting.

For constraints, always help coaches answer:

- What if it is too easy?
- What if it is too hard?
- What if it gets weird?
- What if nothing changes?
- What if players game the scoring?
- What if I picked the wrong constraint?

This reduces fear and makes coaches more likely to use the idea.

---

# 17. Completion Must Produce a Concrete Artifact

The course should end with something the coach can use.

For this course, the final artifact is an **Activity Upgrade Plan**.

## Activity Upgrade Plan Fields

- Activity I already use
- Problem I want to solve
- What players need to notice
- Constraint I will add or change
- How scoring/rules will work
- Coaching question I will ask
- If it is too easy
- If it is too hard
- If it gets weird
- What I will watch for

The course is not complete until the coach has built this.

---

# 18. Quality Control Checklist

Before approving any module, ask:

1. Does this help the coach use the idea tomorrow?
2. Does it avoid unnecessary jargon?
3. Does it include interaction?
4. Does it include at least one visual teaching moment?
5. Does it give useful feedback?
6. Does it build part of the final artifact?
7. Does it work for multiple team sports?
8. Does it feel modern and visually clean?
9. Does it make practice design feel simpler, not harder?
10. Would a busy coach actually finish this?

If the answer is no, simplify the module.

---

# The Core Constraint for the Course

The course itself should follow the same principle it teaches:

**Do not add complexity to look clever.  
Design the learning experience so the next useful action becomes clear.**
